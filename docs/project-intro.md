# 这个项目想做什么 —— 写给第一次来到这里的人

> 时痕 · STE（SpatioTemporal Entity Schema；原「时迹 · TimeTrace」，2026-08-27 更名）。这是一份尽量说人话的介绍。
> 最后更新：2026-08-27。

## 从一个问题开始

你小时候上的那所学校，现在还在吗？

不是问"它还办不办"，而是问一个更奇怪的事实：**如果你打开任何一款地图，搜它的名字，你大概率什么都找不到**。它可能改过三次名，搬过两次家，二十年前被合并，原址现在是一个小区。地图告诉你那里有楼房、有商铺、有公交站，唯独不告诉你——那里曾经是你的学校。

地图是一种只有"现在"的媒介。它擅长回答"这里有什么"，却从来不回答"这里**曾经**有什么"。而城市每天都在改名、合并、拆除、迁址，"曾经"正在以惊人的速度消失——不是消失在人们心里，是消失在一切可以被检索、被引用、被传承的地方。

这个项目想补上这一维。

## 我们的答案：给每个地点建一条时间轴

现有的地图数据里，一个地点是一条记录：一个名字、一个坐标、一组标签。名字变了，就把记录改掉——旧名字就此蒸发。

STE（SpatioTemporal Entity，时空实体）的做法不同：**一个地点不是一条记录，而是一条时间轴**。它有一个永远不变的 ID 和坐标，然后是一串按时间排列的快照，每个快照说一件事：在这段时间里，它叫什么、是什么、在哪里、状态如何。

一所学校的 STE 档案长这样（简化示意——真实档案还需顶层 `name` 等字段，UUID 也必须是真生成的）：

```jsonc
{
  "ste_id": "……永远不变的 UUID……",
  "ste_version": "0.2",
  "coordinates": { "lat": 39.92, "lon": 116.39 },
  "timeline": [
    { "start_date": "1953", "end_date": "1978-06", "name": "某某中学", "type": "school",
      "sources": ["市教育志（示例）"] },
    { "start_date": "1978-09", "end_date": "2001", "name": "某某第一中学", "type": "school",
      "sources": ["市教育志（示例）"] },
    { "start_date": "2002", "end_date": "2015-05", "name": "某某实验中学", "type": "school",
      "coordinates": { "lat": 39.94, "lon": 116.41 }, "status": "relocated",
      "sources": ["区教育局公告（示例）"] },
    { "start_date": "2015-06", "end_date": "2015-08", "name": "某某实验中学", "type": "school",
      "status": "demolished",
      "sources": ["新闻报道（示例）"] }
  ]
}
```

注意时间段的衔接是错开的——因为规则规定 `end_date` 按闭区间算，前后两段首尾相接就算重叠，校验器会拒绝。改了名？时间轴上多一个快照，旧名字还在。搬了家？快照里记下新坐标，轨迹还在。拆了？标记拆除时间，**记录本身不会被删掉**——因为"它曾经存在过"恰恰是最重要的那条信息。

这就是全部核心思想。剩下的所有设计，都是为了让这个思想在真实世界里可靠地运转。

## 为什么不直接改 OpenStreetMap？

我们很认真地对齐现有的开放地图生态，而不是另起炉灶：

- STE 的字段命名直接复用 OSM/OHM（OpenHistoricalMap）的惯例——`start_date`、`amenity`、`tags`，现有的 OHM 工具能部分读懂 STE 数据；
- 每个实体可以携带 Wikidata、OSM、维基百科的外部 ID，和更大的知识网络互相引用；
- STE 自有的东西（叙事、证据链）用 `ste_` 前缀清楚隔开。

换句话说：**STE 想做 OSM/OHM 的超集，而不是平行宇宙**。OHM 是伟大的平台，但它是"平台优先"的——缺一个实体级的、可以独立校验、独立交换、独立存档的轻量格式。STE 补的是这一层。2026 年 8 月，我们用 Overpass API 抓了一批 OSM 社区真实维护的北京历史要素做导入测试：所有语义完整的记录都无损通过了 STE 的双重校验，转换不了的（比如野生日期格式 `2004.7`）被如实隔离并注明原因，而不是被悄悄"修"掉。兼容性不是嘴上说说，是跑过的。

## 比格式更重要的：这些数据可信吗？

这可能是本项目和其他"历史地图"最大的区别，也是我们花心思最多的地方。

我们正处在一个 AI 可以批量生成"历史"的时代。让 AI 总结一所学校的沿革，它会给你一段通顺、自信、细节丰富、**可能是编的**文字。如果这样的内容不加标记地进入数据集，三年之后就没有人能分清哪些是人类考证过的史实，哪些是模型的想象。

所以 STE 把"可信度"做成了数据格式本身的强制组成部分，而不是事后补丁：

- **没有来源，就没有数据**（规则 R1）。每条记录必须标注来源，来源可以是档案、新闻、口述、官方名录——但必须是可查的东西。没有来源的内容最多在草稿区待 30 天。
- **AI 生成的内容必须自我申报**。带有 `ai_generated` 标记和自报置信度，界面上不得和人类口述混同展示。我们甚至要求界面如实告诉用户"这个置信度是 AI 自己说的"，不许包装成"平台认证"。
- **事实和叙事分开放**。一处地方的"事实描述"要求中性简短；而"我记忆中的它"——亲历、转述、研究整理、AI 生成——进入多视角的叙事层，每种视角都标注作者身份。两个有来源的叙事打架时，平台**并列展示两边的证据，不替你选哪个对**。
- **撤回可以，但不能毁尸灭迹**。贡献者有权撤回自己的内容，但会留下一块"墓碑"：此处曾有一条证据，于某日应作者要求撤回。引用了它的内容会自动降信。
- **领土与归属，永远带着时间说话**。平台不展示任何无时间限定的归属声明，只有"YYYY–YYYY 年间，据某来源，此地属 X 管辖"。同一个时段有多个有来源的主张？并列。

这些规则写在一份公开的[伦理宪章](../ETHICS.md)里。宪章里最根本的一条是：**我们不制造"官方版本"的历史**。事实的信度由来源、证据、社区确认共同决定，平台对观点中立，但对证据方法不中立。

## 现在有什么

这个项目还很年轻（2026 年 8 月初创建），但已经不是一纸空文：

- **STE Schema v0.2**：上文说的那套数据格式，中英双版本，附带 25 条逐规则负向测试和一个 103 检查点的参考校验器（因为很多规则——比如"时间轴上的时间段不许重叠"、"2 月 30 日不是合法日期"——是 JSON Schema 本身表达不了的，我们如实把它们列出来，并用代码守住）。
- **一个能玩的 demo：[「曾经的母校」](https://wonderingwu.github.io/ste-schema/demo/)**。北京、上海 77 所有据可查的消失、更名、迁址中小学，外加西南联大、圣约翰、金陵等 12 所历史名校——近九十所学校，每所都有完整的时间轴（另附一个演示城市，供你上手体验"留记忆"的功能）。拖动时间滑块，你能看到它们在地图上出现、改名、搬迁、消失；你也可以为自己的母校留下一条记忆、一张照片。
- **治理文件公开**：伦理宪章、项目治理（许可怎么分层、质量门怎么设）都在仓库里。许可本身也是分层的——代码 MIT，标准文本 CC0（谁都可以零摩擦地用这套格式），数据集 ODbL（和 OSM 生态同一规则）。

## 也必须诚实地说的

- 目前只有**一位维护者**，数据规模是几十所学校而不是几万。它是一个高质量的起点，还不是一个生态。
- 部分实体坐标是城区级近似（数据里已如实标注低置信度），逐点精化是长期工作。
- 宪章里有些条款（比如托管匿名的加密存储、争议委员会）还是纸面承诺，仓库里对每条都标注了实现状态。我们选择把"还没做到"写出来，而不是假装做到了。
- 项目的历史比代码更短——欢迎带着怀疑使用它，更欢迎带着证据质疑它。质疑本身，就是这个系统设计的养料。

## 接下来

- **v0.3**（提案已在仓库 `docs/proposals/`）：实体的合并/拆分/废弃语义（一所学校拆成两所，是历史地理的家常便饭）、质疑与批注的数据结构——让"我不同意"也成为一条有格式的数据。
- **v1.0**：事件模型与实体关系（"西南联大"和北大、清华、南开的关系，不该只是三段孤立的文字）。
- 与 OHM、Wikidata 社区的正式对话；更多城市；更多"曾经的什么"——不只学校，还有工厂、影院、街道。

## 你可以怎么参与

- **玩一玩** [demo](https://wonderingwu.github.io/ste-schema/demo/)，找找你的母校还在不在；不在的话，给它留名——留名数据会真实影响我们先开哪座城。
- **想一想** 你知道的某个"曾经"：一所消失的学校、一家关门的影院、一条改名的街。它能说出时间、地点、来源，就是一条 STE 数据的雏形。
- **挑一挑** 格式设计的毛病。协议在 [v0.2/schema.json](../v0.2/schema.json)，提案和兼容性报告在 `docs/`，issue 区欢迎一切带证据的反对意见。

历史无法完全抵达，但证据可以透明、争议可以可见、方法可以复现。这就是我们想建的：一个让世界不丢记忆的容器。
